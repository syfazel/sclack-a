# D3 — وب‌سایت sclack_A: اسکلت + چت (پیش‌نویس آمادهٔ استقرار)

**وضعیت:** مستقر و زنده است (پوش `c01ab9c` + ران تازهٔ Pages؛ آدرس زنده باندل
ساخته‌شده را می‌دهد)؛ تست زندهٔ سرتاسری D3 هم سبز شد. تغییر رمز (دنبالهٔ D2)
در این پیش‌نویس آمادهٔ پوش است — به بخش «تغییر رمز داخل سایت» پایین نگاه کنید.
**D4 (سند و فایل) در همین پیش‌نویس ساخته شد — به بخش «D4 — سند و فایل»
پایین نگاه کنید؛ استقرارش با پوش تازه انجام می‌شود.**

## استک (قفل‌شده با تپ یاسین)
Svelte 5 + Tailwind v4 + DaisyUI v5 روی Vite 8. مسیریابی هش (`#/room/...`)،
رفرش کار می‌کند. ظاهر گرم مرحلهٔ ۵ (کرم، کهربایی/مرجانی، راست‌به‌چپ، وزیرمتن).
بنفش فقط برای دستیار میوز است و در D3 هیچ بنفشی نیست (دستیار در D3 نیست).

## ساختار
- `src/lib/supabase.js` — کلاینت Supabase؛ کلید فقط از
  `VITE_SUPABASE_PUBLISHABLE_KEY` در زمان بیلد. بدون کلید، `sb = null` و اپ
  اعلان «کلید وصل نشده» نشان می‌دهد.
- `src/lib/auth.js` — ورود/ثبت‌نام/خروج، اعتبارسنجی ایمیل ثبت‌نام (همان منطق
  پروب W0: دامنه‌های رزرو/غیرقابل‌ارسال با ذکر دامنه رد می‌شوند)، متن دقیق
  خطای Supabase، حالت کهربایی سقف نرخ (429)، ساخت ردیف members با
  `muse_id = 'auth:' + uid` و `auth_id = uid` (upsert روی `auth_id`).
- `src/lib/data.js` — خواندن پروژه‌ها/اتاق‌ها/اعضا، ساختن پروژه (نام + یک تپ)
  با اتاق خودکار «گفت‌وگو». سند خودکار «سند» در D3 ساخته نمی‌شود (مال D4 است).
- `src/lib/chat.js` — چت: خواندن پیام‌ها، کانال خصوصی Realtime
  (`private: true` — دسترسی عمومی Realtime خاموش است؛ بدون آن اشتراک با
  PrivateOnly رد می‌شود)، حضور و تایپ با Broadcast روی همان کانال، دکمهٔ
  فرستادن هیچ‌وقت غیرفعال نمی‌شود و هر کلیک دلیلش را در خط وضعیت می‌گوید.
- `src/components/` — Login ،Sidebar (سوییچر پروژه، فهرست اتاق، ۴ جای عضو)،
  ChatView ،HomeView ،RoomsView ،MembersView ،PlaceholderView (کارها، موقت تا D5).
- `src/App.svelte` — مسیریابی هش، پوسته، ناوبری پایین موبایل (۴ مقصد، ۴۴px).

## قانون کلید — سفت
- هیچ مقدار کلیدی در هیچ فایلی نیست (نه کد، نه `.env`، نه کامیت، نه چت).
- کلید publishable فقط از GitHub Actions Secret با نام
  `VITE_SUPABASE_PUBLISHABLE_KEY` در زمان بیلد تزریق می‌شود (ورک‌فلو در
  `.github/workflows/pages.yml`).
- کلید قدیمی anon (JWT) هیچ‌جا نوشته نمی‌شود. صفحهٔ پروب W0 فقط آن را
  می‌پذیرفت؛ سایت تازه با supabase-js ‏2.119 کلید publishable را می‌فهمد.
- **dist بدون کلید هرگز مستقیم مستقر نمی‌شود:** در `src/lib/supabase.js`
  کلاینت مشروط ساخته می‌شود (`sb = isConfigured ? createClient(...) : null`)،
  پس در بیلد محلی بدون کلید Rollup کل `@supabase/supabase-js` (شامل auth-js و
  realtime-js و storage-js و postgrest-js) را حذف می‌کند — باندل dist پیش‌نویس
  ذاتاً بدون کلاینت است (۳۲۷٬۸۱۲ بایت در برابر ۵۵۰٬۷۴۲ بایت باندل زنده که با
  کلید ساخته شده) و قابل استقرار مستقیم نیست؛ استقرار فقط از راه بیلد CI با
  سیکرت انجام می‌شود. کاوش‌ها فقط با بیلد خودساز با کلید جای‌نگهدار معتبرند
  (همان انضباط پروب‌ها: refuse به mount باندل بدون probe-ref) و پس از هر
  کاوش `npm run build` بدون env dist تمیز را برمی‌گرداند (صفر probe-ref).

## اجرای محلی (بدون کلید واقعی — هرگز کلید واقعی را در `.env` ننویسید)
```
npm install
npm run dev        # صفحهٔ ورود با اعلان «کلید وصل نشده» بالا می‌آید
npm run build      # بیلد پروداکشن؛ بدون کلید هم سبز می‌شود
```
برای آزمودن مسیر تزریق، بیلد با یک مقدار جای‌نگه‌دارِ آشکارا جعلی انجام شد
(`PLACEHOLDER-NOT-A-REAL-KEY`) و مقدار در باندل نشست (اثبات مسیر)؛ بعد بیلد
تمیز بدون کلید بازسازی شد و جای‌نگه‌دار از باندل پاک شد.

## تغییر رمز داخل سایت (دنبالهٔ D2 — ۲۱ نوامبر ۲۰۲۶)
- **چی اضافه شد:** بخش «تغییر رمز» در نوار کناری (Sidebar)، بالای دکمهٔ خروج؛ با
  تپ روی «تغییر رمز» باز می‌شود: سه فیلد رمز فعلی / رمز تازه / تکرار رمز تازه +
  دکمهٔ «ذخیرهٔ رمز تازه» (دکمهٔ اصلی کهربایی، ۴۴px، گردی ۱۴px — سیستم دکمهٔ
  مرحلهٔ ۶). برچسب‌ها فارسی، بدون ایموجی.
- **کجا:** منطق در `src/lib/auth.js` (`validateChangePassword` +
  `changePassword`)؛ UI در `src/components/Sidebar.svelte`.
- **چطور کار می‌کند:** اول اعتبارسنجی سمت کاربر (هر سه فیلد پر، رمز تازه
  دست‌کم ۶ نویسه، تکرار با رمز تازه یکی، رمز تازه با فعلی فرق کند)؛ بعد
  `signInWithPassword` با ایمیل نشست + رمز فعلی (اثبات دانستن رمز فعلی) و
  سپس `updateUser` با رمز تازه. خطای Supabase با متن دقیق خودش نشان داده
  می‌شود. پس از موفقیت فیلدها پاک می‌شوند و کاربر همچنان وارد است
  (ورود دوباره نشست را تازه می‌کند).
- **راستی‌آزمایی:** فقط بیلد محلی + حضور UI در صفحهٔ زنده؛ با هیچ حساب واقعی
  تست نشده است (تست سرتاسری با حساب واقعی بر عهدهٔ والد است).

## استقرار (پس از تأیید یاسین)
1. کلون تازه: `git clone https://github.com/syfazel/sclack-a.git`
2. محتوای همین پوشه (به‌جز `node_modules` و `dist`) را در کلون بریزید؛
   `index.html` پروب W0 را به `archive/w0-probe.html` منتقل کنید (در تاریخچهٔ
   گیت می‌ماند؛ دیگر ایندکس زنده نیست).
3. کامیت و پوش به `main`.
4. تغییر Pages به بیلد ورک‌فلویی:
   `gh api -X PUT repos/syfazel/sclack-a/pages -f build_type=workflow`
5. ساخت کلید publishable تازه از داشبورد Supabase **با یاسین** و افزودنش به‌عنوان
   Secret ریپو با نام `VITE_SUPABASE_PUBLISHABLE_KEY`.
6. سبز شدن بیلد Pages و `curl https://syfazel.github.io/sclack-a/` را چک کنید.
7. تست زندهٔ سرتاسری (با کلید واقعی + حساب ساخته‌شده از داشبورد، از راه مرورگر):
   ورود، ساختن پروژه، فرستادن پیام، رسیدن پیام از کانال خصوصی.

## D4 — سند و فایل (۲۱ نوامبر ۲۰۲۶)

- **وابستگی‌ها:** `yjs@13.6.33` + `y-protocols@1.0.7`؛ `jsdom` فقط devDependency
  برای پروب مانت (در باندل نمی‌آید).
- **سند مشترک (`src/lib/yjs-sync.js` + `src/lib/docs.js` + `src/components/DocView.svelte`):**
  ویرایشگر Yjs با `Y.Text('content')`؛ اتصال textarea با diff پیشوند/پسوند
  (تغییر محلی caret را دوباره جابه‌جا نمی‌کند؛ فقط تغییر راه‌دور اعمال می‌شود).
  مسیر `#/doc/<id>`؛ فهرست سندها در نوار کناری و خانه؛ ساختن سند = نام + یک تپ.
  - **مسیر ۱ — BroadcastChannel (زنده):** پیام‌های sync و awareness
    y-protocols روی `BroadcastChannel('sclack-a-doc-<yjs_doc_id>')`؛ ویرایش‌ها
    بین تب‌های همین مرورگر بدون ریلود می‌رسند؛ حضور «نام · نویسهٔ N» از
    awareness می‌آید (نویسه = جای caret در متن؛ حالت‌های کهنه‌تر از ۳۰ ثانیه
    هر ۱۰ ثانیه هرس می‌شوند).
  - **مسیر ۲ — ردیف (ماندگار، بین مرورگرها):** اسنپ‌شات کامل حالت سند به‌صورت
    base64 در `docs.custom_fields.yjs_state_b64`؛ ذخیره = خواندن ردیف، ادغام
    حالت تازه‌تر در سند محلی، بعد نوشتن اسنپ‌شات ادغام‌شده (هر ۲ ثانیه پس از
    آخرین ویرایش، + هنگام پنهان‌شدن تب و خروج). ذخیره‌های راه‌دور با اشتراک
    Realtime UPDATE روی ردیف سند می‌رسند و ادغام می‌شوند. جدول `versions`
    عمداً برای لاگ به‌روزرسانی استفاده نشده است (ردیف‌هایش تغییرناپذیرند و
    سیاست حذف ندارند — لاگِ هر ذخیره برای همیشه رشد می‌کرد)؛ versions مال D5
    (نقطه‌های بازیابی) است.
  - **مسیر ۳ — y-websocket: وجود ندارد.** هیچ سروری ساخته نشده و هیچ کدی
    ادعای کارکردنش را نمی‌کند (U6).
  - **محدودیت صادقانه:** همگام‌سازی زنده فقط بین تب‌های همین مرورگر است؛
    بین مرورگرهای مختلف محتوا با تأخیر ذخیرهٔ ردیف (‎~۲ ثانیه) می‌رسد و
    حضور (presence) فقط در همان مرورگر دیده می‌شود. این در خود صفحهٔ سند هم
    نوشته شده است.
- **نظر (`comments`):** نظر برای کل سند یا برای متن انتخاب‌شده؛ لنگر =
  RelativePositionهای Yjs + نقل‌قول متن (تا ۱۲۰ نویسه)؛ دکمهٔ «رفتن به محل»
  انتخاب را در ویرایشگر می‌گذارد؛ حل‌شده/بازکردن دوباره.
- **سند خودکار:** `createProject` حالا کنار اتاق «گفت‌وگو»، سند «سند» را هم
  می‌سازد (`src/lib/data.js` + `createAutoDoc` در `docs.js`).
- **فایل (`src/lib/docs.js` + `src/components/FileList.svelte`):** باکت
  **`sclack-files`**، چیدمان پوشه `<project_id>/…`، سقف هر فایل **۵ مگابایت**
  (مثل اسپیس)؛ آپلود به Storage + ردیف در جدول `files`؛ دانلود با لینک
  امضاشدهٔ یک‌ساعته؛ حذف (فقط مالک؛ RLS هم همین را می‌گوید). فایل را می‌شود
  به پروژه، سند یا اتاق پیوست کرد (`attached_to_type/id`)؛ فهرست فایل در خانه
  (پروژهٔ جاری)، در صفحهٔ سند و در پنل جمع‌شوندهٔ «فایل‌های اتاق» در چت هست.
  اگر باکت هنوز ساخته نشده باشد، آپلود با پیام فارسی روشن رد می‌شود
  («باکت فایل هنوز ساخته نشده است») — نه با خطای خام Supabase.
- **سیاست‌های Storage:** `workspace/goals/sclack-a/files/d4-storage.sql` —
  فقط فایل، اجرا نشده است. ۴ سیاست `d4 project files …` روی
  `storage.objects` برای باکت `sclack-files`؛ دیده‌شدن پوشهٔ پروژه با همان
  محمول w1 (پروژهٔ team/project برای همه، personal فقط سازنده‌اش) + مالک.
  **ترتیب: اول باکت از داشبورد ساخته شود (خصوصی)، بعد SQL اجرا شود.**
